# 08 · Database and API change plan

All changes use Django migrations. Tenant-DB migrations are **expand/contract** and roll out with
`migrate_tenants` (canaries → one cell → all), because schools upgrade in waves. No manual production edits.

## 1. Control-plane database

| Phase | Change | Type |
|---|---|---|
| 1 | `User.terms_accepted_at`, `User.terms_version` (consent record) **(done: migration 0003)** | Expand |
| 1 | `PlatformStaff(user, role, is_active, created_at)` **(done)** | New |
| 1 | `PlatformAuditEvent` + `PlatformAuditHead` (hash-chained; append-only trigger in migration 0004) **(done)** | New |
| 3 | `SchoolRegistration` (owner, school details, status, review fields, tenant); one pending per owner and one live per slug **(done: migration 0003)** | New |
| 3 | `Tenant.school_type`, `Tenant.region`, `Tenant.registered_by` | Expand |
| 3 | `OnboardingStep(tenant, key, completed_at, completed_by)` | New |
| 4 | `Plan`, `PlanModule`, `Subscription`, `EntitlementOverride`, `TenantModule`, `ModuleActivationEvent` (see 05) | New |
| 7 | `SupportAccessGrant(tenant, requested_by, approved_by, reason, scope, starts_at, expires_at, revoked_at)` | New |
| 7 | `PlatformInvoice`, `PlatformPayment` (school pays Nex Edu; Paystack subscriptions in GHS) | New |
| 7 | `TenantExport(tenant, requested_by, status, file_key, expires_at)` | New |

Constraints to add: one active `Subscription` per tenant (partial unique), one `TenantModule` per
(tenant, module_key).

## 3. API (all under `/api/v1/`, OpenAPI generated by drf-spectacular, TS types by `openapi-typescript`)

| Phase | Endpoint | Notes |
|---|---|---|
| 1 | `GET /me` gains `platform_roles` **(done)** | Existing endpoint, additive |
| 1 | `GET /platform/tenants/` **(done)** | First platform endpoint; super admin and support |
| 2 | `GET /me/workspace` | School, roles, permissions, effective modules, onboarding state |
| 2 | `PUT /school/branding` (multipart logo) | Validated, re-encoded, size-limited |
| 3 | `GET/POST /registrations/`, `GET /registrations/slug-check/` **(done)** | Signed in with a verified email; submissions rate-limited |
| 3 | `GET/POST /onboarding/steps` | Per school |
| 4 | `GET /modules`, `POST /modules/{key}/activate`, `POST /modules/{key}/deactivate`, `GET /modules/{key}/history` | School admin |
| 7 | `/platform/tenants`, `/platform/plans`, `/platform/subscriptions`, `/platform/support-grants`, `/platform/audit` | Platform staff only; separate permission class `IsPlatformStaff(role)` |

The existing test `test_public_endpoints_are_exactly_the_expected_ones` is updated deliberately for each new
unauthenticated or tenant-less endpoint, so nothing becomes public by accident.

API versioning: additive changes stay in `v1`. A breaking change introduces `v2` for that resource and keeps
`v1` until the mobile app's minimum supported version no longer uses it.
